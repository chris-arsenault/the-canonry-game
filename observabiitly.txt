## Consistency pass — what I'm reconciling

A few things drifted across the prior messages; resolving before the doc:

1. **PrimitiveKind.** Earlier I listed `Int32, Float32, IdPair, Bitfield`. Drop `IdPair` and `Bitfield` from the primitive axis. PrimitiveKind matches the *storage shape of one slot* — `Int32` or `Float32`, full stop. 64-bit identity or packed flags are expressed as two `Int32` slots plus a semantic that joins them.
2. **Correlation.** I waffled between `BatchStart/End` brackets and a `PlanId` slot. Picking `PlanId`-style correlation IDs as the primary mechanism (survives drops, reordering, multi-consumer pacing). Brackets remain available for genuinely scoped sequences but are not the trace correlation strategy.
3. **ExternalRef.** Keep, but narrow the use: for payloads that genuinely can't be split into events (rare in this domain). Planner traces never use it — they split.
4. **Schema metadata visibility.** `SchemaRegistry` is `Engine.Eventing.Schema`, not imported by `Engine.Kernel`. Generated `Emit*` methods live in `Engine.Eventing` and are the only schema-aware surface the kernel touches.
5. **Slot counting.** `KernelEvent` = header (`EventType`, `Tick`, `WorldVersion`) + 10 `Int32` + 2 `Float32`. Every schema declaration must fit. No exceptions; overflow is splitting or `ExternalRef`.

# Design Doc: Kernel Event Log, Planner Events, Trace Schema

## 1. Storage record (unchanged)

```
KernelEvent {
    EventType    : u16
    Tick         : u32
    WorldVersion : u32
    Int0..Int9   : i32
    Flt0..Flt1   : f32
}
```

Value type. Packed. Written via `bool TryWrite(in KernelEvent)`. This is the only kernel-facing event API.

## 2. Schema layer

One source of truth per event, declared in `Engine.Eventing`:

```csharp
[KernelEvent(Id = 101, Name = "GoalConsidered", SchemaMinor = 0)]
public readonly partial struct GoalConsidered
{
    [Slot(0)] public required PlanId      Plan;
    [Slot(1)] public required EntityId    Entity;
    [Slot(2)] public required GoalId      Goal;
    [Slot(3)] public required int         CandidateIndex;
    [FloatSlot(0)] public required float  PreliminaryScore;
}
```

Slot indices are positional in the underlying `KernelEvent`. Semantic kind is derived from the field type (`PlanId`, `EntityId`, `GoalId` are wrapper structs over `i32`, each carrying its `SemanticKind`). Raw `int`/`float` requires explicit `Semantic = SemanticKind.RawScalar`.

### Generator outputs

For each declaration:

1. `Emit` extension on the writer:
   ```csharp
   public static bool Emit(this IEventWriter w, in GoalConsidered ev, Tick t, WorldVersion v);
   ```
   Body: zero-init `KernelEvent`, set header, set slots from constants, `TryWrite`. No registry access at runtime.

2. Zero-copy view:
   ```csharp
   public readonly ref struct GoalConsideredView { ... }
   public static GoalConsideredView AsGoalConsidered(in this KernelEvent e);
   ```

3. Registry entry contributed to `SchemaRegistry` at startup (constant data).

4. Round-trip test stub (pack → view → equality).

### Slot kinds

```
PrimitiveKind  : Int32 | Float32                          // storage shape
SemanticKind   : EntityId | FactionId | GoalId | PlanId
                 | AttributeId | ProcessId | RelationshipKindId
                 | ResourceId | ReasonCodeId | EnumOf<T>
                 | RawScalar | Strength | Tick | ExternalRef
```

`SemanticKind` is the contract that prevents primitive-clothing degeneration. Every slot has both. Adding a new semantic kind is a deliberate registry-level change.

## 3. Project boundaries

```
Engine.Kernel       → Engine.Eventing (writer + Emit extensions only)
Engine.Eventing     → (schema declarations + generated code + ring buffer + cursors)
Engine.Eventing.Schema → SchemaRegistry, SlotDef, EventSchema    (consumer-side metadata)
Engine.Projection.* → Engine.Eventing.Schema + domain registries
```

Analyzer rule in `Engine.Kernel`: imports of `Engine.Eventing.Schema` are forbidden. Imports of any namespace containing `string`-bearing schemas are forbidden.

## 4. Overflow and versioning

- **Splitting** is the primary overflow tool. Use a correlation ID slot (`PlanId`, `BatchId`, etc.) to let consumers reassemble.
- **`ExternalRef`** is for genuinely unsplittable bulk data. The slot holds a handle into an `Engine.Eventing` side-store keyed `(EventTypeId, PayloadId)`. Append-only, tick-scoped retention.
- `EventTypeId` is immutable. Breaking changes allocate a new ID and mark the old `[Deprecated]`. Additive changes (using a previously unused slot) bump `SchemaMinor`. Recorded streams remain decodable.

## 5. Planner event schemas

Correlation: every planner event carries `PlanId` in `Slot 0`. A `PlanId` is a `i32` issued by the planner monotonically per planning invocation, scoped to a `(Tick, EntityId)`.

```
PlanStarted (id=100)
    Slot0: PlanId        Slot1: EntityId
    Slot2: PlanReasonCodeId   Slot3: CandidateCount

GoalConsidered (id=101)
    Slot0: PlanId        Slot1: EntityId
    Slot2: GoalId        Slot3: CandidateIndex
    Flt0:  PreliminaryScore

GoalScored (id=102)
    Slot0: PlanId        Slot1: EntityId
    Slot2: GoalId        Slot3: ReasonCodeId   (which scoring rule fired)
    Slot4: ScoringPassIndex
    Flt0:  ScoreDelta    Flt1: RunningTotal

GoalSelected (id=103)
    Slot0: PlanId        Slot1: EntityId
    Slot2: GoalId
    Flt0:  FinalScore

PlanStepEmitted (id=104)
    Slot0: PlanId        Slot1: EntityId
    Slot2: GoalId        Slot3: StepIndex
    Slot4: ProcessId     Slot5: TargetEntityId
    Slot6: RelationshipKindId   (or unused = 0)

PlanCommitted (id=105)
    Slot0: PlanId        Slot1: EntityId
    Slot2: StepCount     Slot3: PlanReasonCodeId
    Flt0:  TotalScore

PlanAbandoned (id=106)
    Slot0: PlanId        Slot1: EntityId
    Slot2: ReasonCodeId
```

All slot values are stable IDs or numerics. No strings. No collections. No live references. `ReasonCodeId` is a domain-registered enum compiled at startup; humans see "score:faction_renown_priority", the kernel sees an `i32`.

## 6. Trace consumer

Lives in `Engine.Projection.Trace`. Reads the primitive stream via its own cursor.

```
Reader loop (off sim thread):
    while (cursor.TryRead(out KernelEvent e)):
        switch (e.EventType):
            case PlanStarted:    open trace tree for e.Slot0 (PlanId)
            case GoalConsidered: append node under (PlanId, "considered")
            case GoalScored:     append score row under (PlanId, GoalId)
            case GoalSelected:   mark winner under (PlanId)
            case PlanStepEmitted:append step under (PlanId, StepIndex)
            case PlanCommitted:  finalize, flush to trace store
            case PlanAbandoned:  finalize as abandoned, flush
```

Reassembly key: `PlanId`. Open traces are held in a consumer-side dictionary keyed by `PlanId`, bounded by a max-open count with LRU eviction (a planner that never emits `PlanCommitted`/`PlanAbandoned` is a kernel bug, but the consumer must not leak memory waiting).

String resolution happens here, not in the kernel:

```
display(GoalId g)        = domain.Goals[g].DisplayName
display(ReasonCodeId r)  = domain.ReasonCodes[r].Description
display(EntityId e)      = projection.Names[e] ?? $"#{e.Value}"
```

The trace store format (JSONL, parquet, sqlite — pick per deployment) is a consumer implementation detail. Multiple trace consumers can coexist with different formats, each on its own cursor.

### Drop / lag policy

Per kernel discipline doc: a slow consumer must not stall the kernel. The trace consumer's policy:

- Bounded ring per cursor; on overflow, drop oldest *open* `PlanId`s and increment a `tracesDropped` counter.
- Partial traces (saw `PlanStarted` but never `PlanCommitted`/`PlanAbandoned` before drop) are flushed as `status=truncated`. This is recoverable signal.

## 7. Adding a new event — the procedure

1. Add a `partial struct` with `[KernelEvent]` and `[Slot(...)]` attributes in `Engine.Eventing`.
2. Build. Generator produces `Emit` and `View` and registers the schema.
3. Call `writer.Emit(in newEvent, tick, version)` from the kernel site.
4. Existing generic consumers (replay, audit, schema dump) handle it automatically. Typed consumers (UI projection, trace) opt in by adding a switch arm on the new `EventTypeId`.

No enum edit, no pack/unpack methods, no kernel API change, no projection scaffolding. The schema declaration is the entire delta.

## 8. Invariant audit (per the kernel discipline doc)

| Invariant | How this design satisfies it |
|---|---|
| No kernel strings | Slots are typed primitives; analyzer forbids `string`-bearing schemas in kernel-emitted events |
| No runtime string lookup | `ReasonCodeId`/`GoalId`/etc. are domain-registered IDs; resolution is consumer-side |
| No hot-path allocation | `Emit` packs an `in` struct into a value `KernelEvent` and calls `TryWrite`; views are `ref struct` |
| Primitive event boundary | Single `TryWrite(in KernelEvent)` API; schema is metadata, not API |
| Multi-head consumers | Schema enables generic consumers; typed consumers use views; both share the same cursor model |
| Explicit overflow | Splitting via `PlanId` correlation is the default; `ExternalRef` is the named escape hatch |
| Deterministic tick order | `Tick` and `WorldVersion` are header fields on every event; reassembly is order-stable per `PlanId` |
